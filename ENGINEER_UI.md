# Интерфейс инженера — 13 октября 2026

Исходные пожелания: «Кнопки инженеров.md». Уточнение пользователя: до назначения
сохраняем «Взять в работу»; топик создаётся только после назначения.

## Карта экранов и состояний

| Экран | Состояние | Кнопки | Переход / результат |
|---|---|---|---|
| Очередь отдела | Новая заявка | Взять в работу; Передать | Назначение и создание топика либо выбор отдела |
| Очередь отдела | Подготовка топика | Нет активных кнопок; виден этап | Дождаться завершения устойчивой операции |
| Очередь отдела | В работе / ожидание клиента | В чат; Закрыть задачу; Передать | Актуальный топик либо служебный ввод в очереди |
| Начало топика | Активная заявка | Закрыть тикет; Передать | Служебный ввод в этом топике |
| Нижняя клавиатура | Активный топик | Закрыть тикет; Передать | Заявка определяется по фактическому топику сообщения |
| Итог закрытия | Ввод текста / подписи | Отменить | Сохранение итога или завершение ввода без закрытия |
| Передача | Выбор отдела | Другие отделы; Отменить | Ввод причины либо возврат к переписке |
| Передача | Ввод причины | Отменить | Очередь нового отдела либо возврат к переписке |
| Карточка | Закрыта / отменена | Нет активных инженерных действий | История сохраняется; удаление по проверенной копии |
| Кнопка | Старый топик / чужой отдел / нет прав | Действие отклоняется | Клиенту служебная надпись не пересылается |

## Реализовано

- Разделены кнопки очереди и топика. Убраны дополнительные кнопки истории и
  ожидания из инженерных карточек; существующие обработчики прежних callback
  сохранены для старых сообщений. Права, назначения и архив не менялись.
- Карточка оформляется обычным HTML: заголовок со статусом, компактные поля
  компании/клиента/отдела/исполнителя, отдельный блок описания. Пользовательские
  поля экранируются; длинные имена и описание ограничены с учётом UTF-16.
- «В чат» ведёт к начальной карточке актуального топика с параметром thread.
- Нижняя клавиатура с двумя кнопками отправляется в топик. Установка отмечается
  в событиях по привязке чат/топик; повтор и перезапуск не дублируют её.
- Текст нижней кнопки обрабатывается до обычной переписки и до ввода итога.
  Проверяются текущий топик, отдел, доступ и существующие права закрытия.
- Во всех инженерных шагах есть «Отменить», отдельно от отмены клиентом заявки.
- Миграция 005 один раз обновляет существующие карточки. Состояния, история,
  вложения и операции удаления не меняются.

## Общие контракты для параллельной клиентской работы

Новые функции сосредоточены в `internal/telegram/engineer_ui.go`. Клиентские
`ticketText`, `clientTicketButtons`, клавиатура и сценарий отмены не менялись.

Общие изменения: в `staff` добавлен вызов `engineerKeyboardAction` перед
перепиской; worker использует отдельные инженерные шаблоны и клавиатуры;
в инженерных подсказках изменён только текст «Отмена» → «Отменить».
`claim:ID`, `close:ID`, `transfer:ID`, `transferdept:ID:DEPT`, `promptcancel:ID`
сохранены. Новое событие `engineer_keyboard_ready` — только установка клавиатуры.
Миграция — `005_engineer_cards`, только `refresh_card`.

Нижняя reply-клавиатура — интерфейс чата, а не доказательство прав. Поэтому
заявка всегда определяется по текущему `message_thread_id`, без глобального
«последнего тикета». Такие же кнопки могут быть видны в очереди; оттуда надо
работать с конкретной карточкой. `is_persistent` просит Telegram показывать
клавиатуру, но фактический вид зависит от клиента. На начальной карточке также
есть две inline-кнопки как доступный альтернативный способ управления.

## Проверка вручную

1. Создать заявку клиентом. В очереди проверить читаемую карточку и только
   «Взять в работу» / «Передать»; топика ещё нет.
2. Взять в работу. В очереди проверить три действия; «В чат» открывает нужную
   тему с дублированной карточкой и двумя inline-кнопками.
3. Нажать нижнюю «Закрыть тикет», отменить ввод, отправить обычное сообщение:
   клиент получает только обычное сообщение, а не надписи управления.
4. Начать передачу; проверить «Отменить» и на выборе отдела, и на причине.
5. Проверить права другого инженера: общаться он может, закрытие сохраняет
   прежние ограничения исполнителя. Нажатия в очереди и старом топике не
   должны менять другую заявку.
6. Перезапустить бота: карточка и клавиатура не дублируются. Закрыть заявку и
   проверить прежний цикл копии/удаления и историю через бота.

## Проверенные API-возможности

Проверено 2026-10-13 по официальной документации Bot API (на странице версия
10.3). Проект использует собственный HTTP-клиент, без стороннего Telegram SDK.
Новые поля передаются явно и проверяются HTTP-тестами.

- [ReplyKeyboardMarkup](https://core.telegram.org/bots/api#replykeyboardmarkup):
  простые кнопки отправляют текст, `is_persistent` — запрос постоянного показа.
- [HTML](https://core.telegram.org/bots/api#html-style): используется `parse_mode=HTML`,
  пользовательские `<`, `>` и `&` экранируются.
- [Ссылки на сообщения](https://core.telegram.org/api/links#message-links):
  ссылка в закрытой супергруппе содержит ID карточки и thread актуального топика.

Цвета, Premium-эмодзи и Rich Messages здесь не требуются: понятность достигается
структурой, короткими названиями и разделением служебного ввода и переписки.
