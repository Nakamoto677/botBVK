# Локальная панель для ручного тестирования

Развёрнута 13 октября 2026 на этом Mac. Вход и запросы проверены на настоящем
Metabase OSS v0.64.1. Панель доступна только через loopback:

**http://localhost:3000/dashboard/1#refresh=60**

В браузере Codex открыт аккаунт `manager1@bvk.local`. Его права — просмотр
дашбордов и выгрузка, без редактирования опубликованной коллекции.
В другом браузере войдите самостоятельно. Новые локальные пароли администратора
и двух руководителей находятся в `data/metabase-local/ACCESS.md`.
Этот файл и остальные runtime-данные исключены из Git; каталог имеет права 0700,
файлы секретов — 0600.

## Обновлённый интерфейс

Корень сайта теперь открывает «Поддержка BVK». Пять вкладок: Обзор,
Требуют внимания, Сотрудники, Подробно, Как читать. На обзоре четыре главных
показателя; подробности открываются нажатием числа и номера заявки.
[Исследование и изменения](ANALYTICS_UX.md).

Для обновления интерфейса без перенастройки доступов:

```sh
python3 scripts/analytics/local.py refresh-ui
```

Перед импортом сохраняется приватная копия предыдущей раскладки. Всего теперь
52 SQL-карточки. Ссылка выше включает минутное обновление открытого экрана.

## Источник и процессы

- Используется существующая БД `bvk_test` контейнера `bot-bvk-postgres-1`,
  опубликованная на `127.0.0.1:55432`. Это локальные данные бота, без добавления
  демонстрационных заявок.
- В момент проверки: **16 поступивших, 12 закрытых, 4 отменённых, 0 активных**.
  Поэтому текущая нагрузка и списки внимания пусты. После появления активных
  заявок в этой же БД они попадут в панель при следующем минутном обновлении.
- Нативный `bin/bvk-analytics` запущен фоновым процессом с ограниченной ролью.
  Он наследует календарь/пороги текущего `config.json`, не запускает Telegram-бота
  и не требует его токена.
- Metabase работает в контейнере `bvk-metabase-local`. Используется официальный
  образ `metabase/metabase:v0.64.1.x`, digest сохранён в локальном runtime.
- База настроек Metabase — отдельная `bvk_metabase` в том же PostgreSQL.
  Учётная запись прикладной БД и читатель аналитики различаются. Источником
  Metabase служит только схема `analytics`.
- До установки сохранена исходная копия
  `data/metabase-local/bot-before-analytics.dump`. Исходные заявки, сообщения,
  архивы и конфигурация бота не изменялись.

## Что проверено

Все 48 SQL-карточек импортированы и выполнены через настоящий API Metabase.
Повторный импорт обновляет объекты без дубликатов. Проверены оба аккаунта
руководителей: просмотр успешен, `can_write=false`, изменение дашборда получает
HTTP 403. Без входа доступ к дашборду получает HTTP 401.

Через браузер проверены вход руководителя, загрузка обзора, выбор отдела по имени,
переход из «Поступило» в точный список с сохранённым фильтром IT (9 заявок),
нажатие номера и открытие карточки с описанием, клиентом, циклом и историей,
переход из числа закрытий сотрудника в список с сохранением выбранного автора.
Снимки обновляются каждую минуту. На текущих данных после исправления служебных
доставок нет предупреждений неполной истории (`incomplete_count=0`).

Во время реального внедрения исправлены:

- API Metabase запрещает пустую строку описания — импортер передаёт NULL.
- Параметр запроса должен содержать ID — добавлен стабильный ID template-tag.
- Начальное описание топика доставляется как `source_message_id=0`,
  `initial_description=true`; это штатная служебная доставка, а не пробел истории
  и не публичный ответ инженера. Добавлена регрессия и обновлён расчётчик.
- Исправлена русская подпись «по компаниям» и подписи операций.

## Запуск и остановка

Команды выполняются из корня проекта, при запущенном Docker Desktop.

```sh
# Если после перезагрузки исходный PostgreSQL остановлен:
docker start bot-bvk-postgres-1

# Запустить или проверить текущую локальную панель:
python3 scripts/analytics/local.py start
python3 scripts/analytics/local.py status

# Остановить только Metabase и аналитику; бота/его PostgreSQL команда не трогает:
python3 scripts/analytics/local.py stop
```

Metabase перезапускается Docker по политике unless-stopped. Для нативного
расчётчика автозапуск при входе в macOS не устанавливался: после перезагрузки
используйте `start`. Не удаляйте исходный Docker volume: в нём находятся обе БД.

Повторный импорт и установка текущих прав:

```sh
python3 analytics/metabase/build.py
python3 scripts/analytics/local.py setup
```

`setup` использует сохранённые локальные ID/секреты; обновляет управляемые карточки,
раскладку и права двух ранее разрешённых тестовых аккаунтов. Он заменит ручные
правки этих дашбордов. При изменении Go-кода расчётчика:

```sh
go build -trimpath -o bin/bvk-analytics ./cmd/bvk-analytics
python3 scripts/analytics/local.py restart-analytics
```

Логи: `data/metabase-local/analytics.log` и `docker logs bvk-metabase-local`.
Параметры и state: `data/metabase-local/secrets.json`, `metabase.env`,
`import-state.json`. Не публикуйте файлы секретов.

## Ручная проверка

1. В «Обзоре» сверить 16 поступивших, 12 закрытых и 4 отменённых.
2. Выбрать отдел/сотрудника/компанию, нажать число и сравнить его со списком.
3. Нажать номер заявки: проверить результат закрытия, автора и историю.
4. Открыть «Сотрудники» и «Требуют внимания», проверить понятность таблиц.
5. Проверить выгрузку и отсутствие редактирования под руководителем.
6. При появлении новой активной заявки в локальном боте подождать до минуты и
   убедиться, что изменились текущие показатели.

Внешний HTTPS и Windows-службы в этом локальном размещении не настраивались.
Инструкция для сервера — [ANALYTICS_DEPLOYMENT.md](ANALYTICS_DEPLOYMENT.md).
