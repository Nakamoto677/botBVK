# Чистая БД для нового Telegram-пилота

Подготовлено 21 октября 2026. Новая PostgreSQL работает отдельно от прежней:
контейнер `bvk-pilot-postgres-1`, порт только на этом Mac `127.0.0.1:55434`,
база `bvk_pilot`, именованный volume `bvk_pilot_postgres_data`. Миграции
`002`–`009` уже применены. Из конфигурации добавлены три компании и один
администратор. Текущие заявки и сообщения пилота сохраняются в этой БД.

## Что заполнить локально

1. В `data/pilot/config.json` проверьте `admin_id`, `staff`, три отдела
   (`it`, `1c`, `field`) и список `companies`. `chat_id` групп и темы очереди
   для этих отделов уже записаны. Отдел «Монтаж» в пилоте отключён. Группа
   компании задана в `client_groups`.
   Корневой `config.json` тоже закреплён за пилотной БД через приватный
   `data/pilot/database.url`: запуск напрямую через `./bin/bvk -config config.json`
   больше не зависит от старого `DATABASE_URL` в терминале.
2. Перед запуском задайте токен **нового** бота в своём терминале:
   `export TELEGRAM_BOT_TOKEN='ВАШ_ТОКЕН'`. Записывать токен в JSON не нужно.
   При желании вместо экспорта можно заполнить `data/pilot/telegram.env`.
3. Добавьте бота в три группы отделов с правами администратора, включая
   управление темами и сообщениями. В каждой группе откройте тему «Очередь»,
   скопируйте ссылку именно на тему и укажите её ID в `queue_topic_id`.
   `2` в первоначальном конфиге было предполагаемым значением и не
   соответствовало созданным темам. Системные обновления Telegram показали
   ID `3` для тем IT, 1С и Выезда; оба пилотных конфига исправлены.
   Команда `check` ниже проверяет чаты, права и доступность указанных тем через
   краткое действие «печатает…» без отправки сообщения.

Пилотный конфиг и файл токена локальные, находятся в игнорируемом Git каталоге
`data/` и созданы с правами доступа только для владельца. Пароль БД уже создан в
`data/pilot/postgres.env` и `data/pilot/runtime.env`; его не надо менять в двух
местах вручную.
`data/pilot/database.url` содержит тот же адрес для прямого запуска бота;
пароль остаётся вне JSON и Git.

## Запуск

Из корня проекта:

```sh
./scripts/pilot.sh up
go build -trimpath -o bin/bvk ./cmd/bvk
./scripts/pilot.sh migrate
export TELEGRAM_BOT_TOKEN='ВАШ_ТОКЕН'
./scripts/pilot.sh check
./scripts/pilot.sh run
```

`migrate` повторно применяет схему без потери записей, синхронизирует компании
и добавляет новых сотрудников из пилотного конфига. Существующие записи сотрудников
эта команда не переписывает. `check` также делает эти шаги, а затем
проверяет подключение и права Telegram. `run` держит бота в переднем плане;
для постоянной работы понадобится отдельный сервис или управляемый запуск.
Статус PostgreSQL: `./scripts/pilot.sh status`.

`check` и `run` берут токен из текущего терминала. `run` остаётся в переднем
плане: остановка через Ctrl+C. После запуска можно проверить готовность командой
`curl -fsS http://127.0.0.1:8081/ready` в другом терминале. Без токена скрипт
сразу скажет, что именно нужно задать.

Если карточка не дошла до очереди из-за неверного `queue_topic_id`, исправьте
ID в обоих `config.json` и `data/pilot/config.json`, перезапустите бот, затем
отправьте администратору `/retry ID` для каждой операции `refresh_card`,
помеченной как неудачная. Повтор не создаёт новую заявку.

Аналитическая схема пилота уже создана, один расчёт успешно выполнен: в витрине
только IT, 1С и Выезд. Чтобы пересчитать её после новых заявок, используйте
`./scripts/pilot.sh analytics-once`. Для постоянного обновления раз в минуту
запускайте `./scripts/pilot.sh analytics-run` отдельным процессом.
Для `analytics-run` токен не нужен. Аналитика должна работать одновременно с
ботом, чтобы витрина обновлялась раз в минуту.

После успешной настройки сделайте проверяемую копию:

```sh
./scripts/pilot.sh backup
```

Результат появится в `data/pilot/backups/<время UTC>/`. Копируйте этот каталог
на независимый носитель. `backup` восстанавливает дамп во временную БД и сверяет
архивные вложения; для неё нужны `pg_dump` и `pg_restore`.

## Старые данные

Прежний контейнер `bot-bvk-postgres-1` и его volume не менялись и не удалялись.
Перед созданием новой БД сохранены:

- `data/backups/legacy-before-pilot/database.dump` — дамп старой `bvk_test`;
- `data/backups/legacy-before-pilot/archive/` — копия локальных файлов вложений.

Дамп проверен настоящим восстановлением во временную БД: 103 заявки,
146 сообщений, 784 события. Временная БД удалена. Эту папку тоже нужно
скопировать вне данного Mac. Второй Docker volume изолирует новую БД, но не
заменяет резервную копию: удаление Docker-хранилища или поломка диска затронет
все локальные volume сразу.

Команду `docker compose down -v` для пилота не используйте: ключ `-v` удалит
его volume вместе с данными.
